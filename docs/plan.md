## 1. 边界

### 做

- 传奇（1.76 体系）的**服务端 + 客户端全部重写**，同仓库（`$WS/mir2`）。
- server：Go，从 `mir2go`（63,867 行）抽取领域层，**重写协议层**。
- client：Rust + SDL3，Windows 发布为单 exe + 资产目录，macOS 仅供开发调试。
- **在体感上与原作一致；在实现上（协议、架构、存储、资产载体）完全自由。**

### 不做

- 不做引擎级重制：不改美术风格、不加新玩法、不重做数值。
- 不为兼容原版客户端做任何协议妥协（D-05）。
- 不做 macOS 发行（.app / 公证 / 双架构）。
- 不做遗留客户端里没有的东西。**功能清单以 28 个窗口 + 消息清单为准**
  （见 [legacy-analysis.md §4](./legacy-analysis.md)），**不要用中文关键词命中数判断**——
  窗口名是英文标识符，关键词法会漏（曾据此误判"不做邮件"，实际存在
  `DMailListDlg` / `DFriendDlg` / `DBlockListDlg` / `DMemo`）。

## 2. 三个不自由的东西

| # | 不自由 | 说明 |
|---|---|---|
| 1 | **美术是内容** | 必须同一套美术。载体（原 WIL / 自研容器）自由，但不能重新画 |
| 2 | **数值是内容** | 物品/怪物/技能/经验表必须与原版一致，改了就变味 |
| 3 | **体感规格的来源是原版** | 协议自由 ≠ 玩法自由。遮挡顺序、动画时序、攻击间隔的判定依据不变 |

其余（网络协议、系统架构、存储、进程划分、资产容器）**全部自由**。

## 4. 架构

### 4.1 仓库布局

```
mir2/
├── docs/          本目录（唯一真源）
├── go.mod         Go 模块：github.com/algotao/mir2（go 1.27）
├── protocol/      ★ 协议单一真源：envelope.proto + 各分段 .proto + version.txt + gen.sh
├── server/        Go
│   ├── internal/  从 mir2go 抽取的领域层（world/entity/magic/script/guild/castle/…）
│   ├── protocol/  生成的协议代码（入库）
│   └── cmd/       gamesvr / accountsvc / gate（进程划分见 §4.3）
├── client/        Rust（Cargo workspace，**两个产物**，见 D-18）
│   ├── protocol/  生成的协议代码
│   ├── core/      纯函数：协议、会话状态机、解码、资产、配置（**无 SDL**）
│   ├── net/       连接、握手、消息泵（独立线程 → channel）
│   ├── e2e/       ★ 产物 1：headless CLI（无显示环境，**禁止依赖 SDL3**）
│   ├── app/       ★ 产物 2：SDL3 界面程序（Windows 发布 / macOS M4 体验）
│   ├── render/    索引纹理 → 调色板查表、Y 序、遮挡、光照   ┐
│   ├── ui/        自绘控件（数据驱动，见 §4.4）              ├ 仅 app 依赖 SDL3
│   └── scene/     地图、Actor、动画状态机、特效              ┘
├── internal/      Go 模块内共享库（`tools/` 与 `server/` 都要用，放不了 server/internal）
│   └── m2pk/      M2PK 地图容器：读写 + 逐字节校验（[assets.md §5](./assets.md)）
└── tools/         资产管线：m2pk CLI（+ `build.sh`）、协议代码生成、数据导入、assetnorm
```

**构建矩阵**见 [D-19](./decisions.md)：**全部原生在 macOS（M4）上开发与构建**；
容器 / CI 降级为**可选**（用途只剩 Linux 部署产物与门禁，尤其大小写敏感检查，见 [D-20](./decisions.md)）。

**Go 模块边界**：**单一模块在仓库根**（`module github.com/algotao/mir2`，`go 1.27`），
`server/` 与 `tools/` 都在其下——这样 `tools/` 能直接引用协议生成代码与领域包，
不必为多模块做 `go.work` 体操（`mir2go` 也是模块在根的约定）。

> 生成的协议 Go 代码放 **`server/protocol/`（非 `internal/`）**，
> 因为 `tools/` 与契约测试驱动需要引用它；`internal/` 会把这些挡在门外。

`.gitignore` 原有 Cargo 段，Go 段已补齐（`server/` 产物、`*.test`、覆盖率、`go.work` 等）。

### 4.2 客户端分层原则

0. **两个产物，一个 `core`**（D-18）。`client/e2e`（headless CLI，无显示环境）与
   `client/app`（SDL3 GUI）**共用 `client/core`**；且 **e2e 必须走与 app 相同的协议编解码与
   会话状态机**，不允许任何"测试专用捷径"。CI 门禁：
   `cargo tree -p mir2-e2e | grep -q sdl3 && exit 1`。
1. **`core` 无 IO**。协议、解码、资产、配置全是纯函数——这是能跑满单测的前提。
2. **动画数据驱动**。遗留是 70 个手写动画类（`AxeMon` 34 + `magiceff` 15 +
   `HerbActor` 10 + `Actor` 9 = 7.6k 行）。新版 = **一个状态机引擎 + 动作表**。
   **不要照搬类的数量。**
3. **UI 数据驱动**。遗留 `FState.pas` 6.8k 行 / **28 个窗口 / 262 个控件**（实测），
   大部分是"坐标 + 图形号"样板。用声明式布局，代码只留交互逻辑。
4. **网络在主循环之外**。收包线程只做拆包 → channel，主循环按帧消费。
5. **定步长逻辑 + 可变帧率渲染**。逻辑 60 Hz 定步长，渲染跟随刷新率。

### 4.3 服务端进程划分（自由度示例）

原版是 7 个进程（LoginSrv / DBServer / M2Server / 三个 Gate / LogDataServer）。
`mir2go` 已收敛为 3 个二进制（`gate` / `accountsvc` / `gamesvr`）。
新协议允许进一步收敛——**建议先用 `mir2go` 的 3 进程划分**（已验证），
不要在这里做创新，把自由度留给真正需要的地方。

其中 `gate` 按 [D-17](./decisions.md) 退化为**纯字节转发层**（接入 / 分帧转发 / 按连接限流 /
连接元数据），**不依赖 protobuf**、不随 schema 演进。按消息类型的限流与审计放到 `gamesvr`。

两条边界按 [D-13](./decisions.md)（待定，含完整分析）：

- **`accountsvc` 不对客户端 Listen**；`gamesvr` 是客户端的**唯一对端**，账号能力走内部 RPC。
  这样客户端只需一条连接、一个状态机，且账号库只有一个 writer。
- **硬约束：一个区组 = 一个 `gamesvr` 进程**（世界状态全局共享，不能横向拆）。
  "多服务器"只能表现为：多区组（多 `gamesvr`）+ 无状态 `gate` 多实例 + `accountsvc` 单实例。

## 6. 排期

| 工作流 | 阶段 | 天 |
|---|---|---|
| 前置 | 消息清单 + 基准版本 + IDL 核心子集 | 3–5 |
| **A 服务端** | 抽取 + 协议改造 + 契约测试 | **17–27** |
| **B 客户端** | M1 + M2 + M3 | **47–65** |
| | 单人串行合计 | **67–97 天（13–19 周）** |
| | **双人并行**（server 一人 / client 一人） | **52–70 天（10–14 周）** |

**依赖关系**：客户端 M2/M3 需要服务端可用。**对策**：M0 就定好 IDL 核心子集，
两端同时开工；服务端未就绪时客户端用 fake server 跑契约测试。
**不要把两端做成串行**——那是本排期里最大的浪费。

**排期单位是「验收点/天」（2–3 个），不是行数**（D-08）。

## 8. 任务池（建议顺序）

1. **[消息清单]**（半天）——216 个 `SM_*` 三档分类 + 与 28 窗口交叉核对。
2. **[基准版本]**（1–2 天）——定 `Client/` 还是 `MirClient/`。
3. **[素材获取]**（非技术，可并行）——D-15。
4. **[IDL 核心子集]**（3 天）——`protocol/mir2.proto` 初稿 + 两端生成脚本。
5. **[服务端抽取 ① ②]**（2–3 天）——复制 + 编译通过，然后删协议层收集失败清单。
6. **[客户端 M1 骨架]**（并行）——窗口 + 主循环 + 合成测试图渲染。
7. **[契约测试骨架]**——必须在 M1 内建立，不能推迟。

## 9. 与参照系统的关系

| 路径 | 角色 | 规则 |
|---|---|---|
| `$WS/mir2go` | 参照系统：抽取来源 + 对拍基准 | **不删、不加功能、禁止双向同步** |
| `$WS/mir2standard` | 体感规格唯一权威（Delphi 源码） | **只读**，⚠️ GBK 编码 |
