**已可确认的资产体量（反衬美术缺失的规模）**：

**待你裁决**：素材从哪来（自有副本 / 购买 / 其它来源）。**在素材到位前，
建议把 M1 的验收标准从"出图无色差"降级为"能解码合成测试图并正确着色"**，

## D-01 技术栈

**状态：已定。**

| 端 | 选型 | 理由 |
|---|---|---|
| server | **Go** | 从 `mir2go`（63,867 行）抽取领域层，省掉最大的重复劳动 |
| client | **Rust + SDL3** | exe 3–5 MB、运行期零依赖、Win/mac 一套代码 |

客户端依赖清单（就这些，全部静态编进去）：

- `sdl3`——窗口 / 输入 / 音频 / 计时 / 线程
- `softbuffer` 或 SDL3 `gpu`——上屏（见 D-07）
- `prost` / `prost-build`——协议代码生成（见 D-12）
- `minimp3-rs` + 自写 WAV 解析——音频
- 字体：**自带点阵字库**（原版本身就是位图字库），零字体依赖

构建参数（体积）：`opt-level="z"`、`lto="fat"`、`codegen-units=1`、`panic="abort"`、
`strip=true`、Windows 加 `+crt-static`。

## D-02 全栈 UTF-8，弃 GBK

**状态：已定。**

**协议自由后，本条从"三个后果要处理"简化成"一条规矩"**：

> 协议层只搬字节；rune 安全的截断/换行只在 UI 层做。

原先因 Delphi `String[N]`（字节口径）而产生的三个后果——**字节容量预算、`EqualFold` 比较语义、
排序口径——全部作废**（不再有定长字节名字段）。

**转码只发生在边界**：

- `mir2go` 侧运行期唯一转码点 `internal/castle/sabuk.go:336 decodeGBK` 必须下沉到导入工具。
- 新 `mir2` 服务端**不允许**出现任何运行期字符集转码。
- 所有 loader 加 `utf8.Valid` 断言：非法即启动失败，不要静默乱码。

**遗留数据导入**：`mir2standard` 的配置、`mir2go` 的 `data/` 都是 GBK 或混合编码，
在**导入那一刻**转成 UTF-8，之后全链路 UTF-8。

## D-03 文件名全小写、无中文、`/` 分隔

**状态：已定。**

**依据**：一次性消灭三个跨平台坑（大小写敏感文件系统、GBK 文件名、反斜杠）。
macOS 默认大小写不敏感，会**掩盖**大小写 bug——由本条一次性消灭。

**新项目是"自己的资产树"，可以完全自己定义**（不再被原版文件名绑架）：

- 资产树由 `tools/` 从 `mir2standard` / `Mir2-GeeM2` **生成**，命名规则自己定。
- 若沿用原版文件名（`Data/Hum.wil` 等），需做规范化：`data/` 侧实测 **855 个大写名 +
  324 个非 ASCII 名**（分布见 [legacy-analysis.md §7](./legacy-analysis.md)）。
- `data/monitems/*.txt`（300 个中文名）**文件名即怪物名**——不要重命名，
  改为索引文件，摆脱"文件名当数据主键"的耦合。

**做法**：一次性 `tools/assetnorm`，产出并提交 `normalize.manifest`（原路径 → 新路径 +
冲突检测）。**不要手工 rename**：

- 仅大小写不同的两个文件在 macOS 上无法共存，而 git 在 mac 上通常
  `core.ignorecase=true`，会**静默忽略纯大小写改名** → 必须两步 `git mv a tmp && git mv tmp A`。
- 规范化若牵动 JSON key，需同步验证数据导出工具的逐字节复现约束。

**收尾**：加门禁，发现大写或非 ASCII 路径即报错。

## D-05 协议自研，不兼容原版报文

**状态：已定（取代原 `mir2client` 的 D-05「沿用遗留字节协议」）。**

**依据**：两端都在自己手里，不再需要兼容原版客户端；原版报文（6bit 码表、
`#<1-9>…!` 字符帧、`TDefaultMessage` 12B + 16 位 `Series`、Delphi `String[N]`、
`DEFBLOCKSIZE=16`、`*/$S/$R`）没有任何保留价值。

**删除的东西**（连带消灭的坑）：

| 原约束 | 现状 |
|---|---|
| `String[N]` 字节容量、中文 2→3 字节缩水 | **消失** |
| `EqualFold` vs `CompareText` 语义差、名字白名单 | **消失** |
| 排序口径（字节序 ≠ 拼音序） | **消失** |
| `codec.PutShortString` 的 `b[:n]` 切坏多字节 | **消失**（风险点蒸发） |
| `TDefaultMessage.Series` 16 位装不下 `ActorId`、必须坐标优先定位 | **消失** |
| 6bit 码表、`#<1-9>…!` 帧、`DEFBLOCKSIZE`、`*/$S/$R` | **全部删除** |

**代价**：`mir2go` 的 46/46 e2e 与 `mir2cli` **不能直接复用**（它们是围绕遗留协议建的）。
它们转而作为 **mir2go 参照系统自身的回归**，不再服务于新项目。

**新增的最大风险**：见 [protocol.md §9](./protocol.md)——**双实现漂移**。

## D-06 美术"同一套、载体自选"

**状态：已定（放宽自原 `mir2client` 的"原格式直读，不转码"）。**

**依据**：体感一致 ⇒ 必须同一套美术；但**载体属于技术实现，可以自由选**。

> 没有这条，"体感一致"就没有证据。

载体方案见 [assets.md](./assets.md)，决策见 D-11。

## D-07 渲染：先 CPU 软件合成，后可选换 GPU

**状态：待定。** 推荐先 CPU。

**依据**：原版本来就是软件混合（`DXRender.pas` 8,081 行，含 JIT 代码生成）。
800×600 = 48 万像素，现代 CPU 完全够，且 CPU 合成**行为天然与原版一致**，零 GPU 兼容风险。
先把"走路 + 打怪"跑通，再按实际观感需求局部替换为 SDL3 GPU。

**约束**：渲染接口边界要在 M1 就设计好，保证后续替换不触碰上层。

**⚠️ 附带约束（体感）**：可以提高分辨率，但**视野格数必须锁死**。
原版视距是玩法平衡的一部分，看得更远 = 更容易。

## D-08 排期单位用「验收点/天」

**状态：已定。** 速率基准 **2–3 验收点/天**。

**依据**：行数指标有四个结构性问题：

1. 诱导写"多行但简单"的代码。照搬 70 个手写动画类能刷出 7.6k 行，
   而一个引擎 + 数据表只要 5k 行 —— **前者行数好看，后者才是对的**。
2. **删除不计入产能**。删掉 46k 行 DirectX 包装在行数上是负数。
3. **评审吞吐是隐形上限**。3K 行/天等于零深度评审，缺陷后移，
   在无自动化验收处（手感、时序、遮挡）以 10 倍代价偿还。
4. 对"移植遗留"不成立——搬迁要先读懂 87k 行 Delphi。

## D-09 验收 = 两端契约测试 + 体感抽查

**状态：已定（取代原"以原版对拍为验收标准"）。**

**依据**：协议自研 ⇒ 一致性不再由"原版客户端能否连上"来判定，而由
**生成的两端实现能否互通**来判定。这是质变：

| | 原（对拍原版） | 现（契约测试） |
|---|---|---|
| 判定者 | **人眼**看截图/抓包 | **自动断言** |
| 覆盖 | 抽样 | 全消息 |
| 回归成本 | 每次手工 | CI |
| 不确定性 | 高（R-2 曾是"无限期风险"） | 低 |

**分工**：

- **协议 / 逻辑 / 数值** → 契约测试（CI 门禁）
- **视觉与手感**（遮挡顺序、帧时序、受击反馈） → 仍需体感抽查，
  在 Windows 上跑 `mir2standard` 原版客户端或 `mir2go` 参照系统对比

契约测试的具体形态见 [protocol.md §9](./protocol.md)。

## D-11 资产载体：自研容器

**状态：待定。** 推荐**自研容器**（而非直读原 WIL）。

| | 直读原始 WIL | **自研容器（推荐）** |
|---|---|---|
| 客户端资产层 | 需写 WIL/WIX 解析器（含偏移坑） | 格式自己设计，最简单 |
| 体积 | 原始 WIL **完全没有压缩** | 每图 zlib/lz4，**体积约减半** |

**理由**：目标是"体积越小越好"，而体积恰恰是资源占的；原始 WIL 未压缩是最大的浪费。
设计见 [assets.md](./assets.md)。

## D-12 协议单一真源：protobuf 3

**状态：已定：protobuf 3。**

**依据**：两端都要生成代码，protobuf 生态最成熟（Go 官方、Rust `prost`），
字段号天然支持演进，调试工具多。高频小包（移动）编码后也只有几字节，开销可接受——
**网络延迟主导，不是带宽主导，不要过早按字节抠**。

**备选**：自研极简 IDL（更少依赖，但要自己写两个 generator，收益不大）。

**硬要求（不论选哪个）**：**禁止手写编解码**，两端实现必须由同一份 schema 生成。

## D-16 消息类型用 oneof 信封，字段号即消息号

**状态：已定。** 完整论证见 [protocol.md §4.1](./protocol.md)。

**结论**：**不设独立的 `msg_id` 字段**。用 `Envelope.body` 这个 oneof 的**字段号**
同时承担「类型标识」与「线上编号」两个角色（`field 0x0503 → EntityMove`）。

**收益（按重要性排序）**

1. **编译期穷尽性**：加一条消息，两端**所有分发点都会编译报错**，逼你处理。
   `msg_id` + `bytes body` 给不了这个——加了消息忘了处理会静默走 default 分支。
2. 类型与编号**只有一处定义**，重命名类型不会漏改编号。
3. 日志直接打印变体名，不再是数字。
4. 省掉每包 3–5 字节的 `msg_id`。

**三条硬规则**

- 字段号**全局唯一、永不复用**；避开 protobuf 保留区 **19000–19999**
  （我们的 `0x01xx`–`0x0Cxx` 完全避开）。
- `oneof` 无法跨文件扩展 ⇒ **字段列表集中在 `protocol/envelope.proto`**
  （消息体仍按模块拆文件）。这份集中列表即"消息总目录"。
- 收到未知消息时 oneof 的 case **未设置** ⇒ 显式处理 `None`：记数 + 告警 + 忽略，
  **禁止 panic**。

**反向条件**（何时该改回 `msg_id` + `bytes`）：需要 gate 做协议感知转发 /
消息数膨胀到几百上千 / 需要协议层可被外部扩展（oneof 无法从外部扩展，是唯一硬限制）。
后者的逃生舱是在信封里留一个 `Raw { uint32 msg_id; bytes body; }` 变体给 GM 与调试用，
不必推翻整体设计。

## D-17 gate 不做协议感知

**状态：已定。**

**依据**：原版三个 gate（LoginGate / SelGate / RunGate）各自拆包，是为了注入真实 IP、
按消息限流等；代价是 gate 必须**理解协议**，跟着 schema 一起变。

新协议下让 gate 退化成**纯粹的 TCP 接入层**：

- 只做：连接接入、4 字节长度分帧的**字节转发**、按连接限流、连接元数据采集。
- 真实 IP 等信息走**内部 RPC 的 metadata** 传给 `gamesvr`，不塞进协议报文。
- gate **不需要**有 protobuf 依赖。

**收益**

- gate 不随 schema 演进；`oneof` 需要完整 parse 的代价问题在 gate 侧直接消失
  （[protocol.md §4.1](./protocol.md)）。
- 进程划分更简单：gate 可以是无状态的（甚至用现成的 L4 代理思路）。

**代价**

- 按**消息类型**的限流 / 审计 / 黑名单要放到 `gamesvr`（gate 只能按连接与字节量限流）。
  这属于可接受的迁移成本。
